AUTHORIZED WEB TESTING — PATCHRIOT PILOT

1. Establish scope and baseline. Fetch the approved homepage, identify redirects without following them outside scope, and inspect the actual content type, headers, resource paths and framework. Collect only the pages needed for the objective.
2. Map the exposed application. Read linked JavaScript and API references on approved origins. Distinguish application routes from SPA fallback pages: a 200 response that repeats the homepage is not a leaked file. Compare hashes, content types and meaningful body text.
3. Form hypotheses before testing. Examples: a sensitive unauthenticated endpoint; reflected input reaching an executable context; an overly permissive CORS response; unsafe cache behavior; an exposed source map with genuinely sensitive content; a redirect that accepts a foreign destination. Use a harmless unique marker and control request. Do not assume a response is vulnerable just because a scanner would flag it.
4. Reproduce within the approved methods. Do not buy, trade, withdraw, change accounts, create stored payloads, enumerate customer records or stress the service. Do not follow discovered credentials. Report the need for a separately approved authenticated or state-changing test when necessary.
5. Verify claims. For CORS, compare trusted, arbitrary and null Origin cases and credentials behavior; public content with a wildcard is not automatically a vulnerability. For reflected input, distinguish encoded text from executable HTML/JS; without browser execution, state that limitation. For exposed files, distinguish intended public configuration from secrets. For redirects, record the exact Location and code.
6. Keep evidence useful. Record request IDs, request method/URL/headers, actual status, relevant excerpts and negative controls. The broker captures bounded evidence; do not claim full-content coverage when truncated. Never put secrets or private customer data into a public report.
7. Challenge severity. State the prerequisite, actual impact and smallest useful fix. Keep confirmed observations separate from hypotheses. The next role should be able to repeat the test from your reproduction text.
8. Keep the report checkable. Every finding needs relevant request IDs from this role. If an earlier claim could not be checked, describe that gap in limitations; do not create a finding with empty or unrelated citations. Read original JSON files in small selected pieces when terminal output is shortened.
